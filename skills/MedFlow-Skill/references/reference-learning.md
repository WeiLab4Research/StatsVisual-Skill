# Reference-informed and independent layout

## With useful reference images

Actually view the user's target and the most relevant available examples; do not substitute filenames for inspection. Usually one to three useful images are enough. Read more only if the structure or appearance remains unclear. Do not repeatedly scan the entire library or chase pixel-level agreement.

Briefly note the transferable features in the proposal: main path and side attachments, peer alignment, text/box balance, relative gaps and visual hierarchy. A separate reference-review.md is optional for complex reproductions, not mandatory paperwork for every figure. Distinguish what was observed from what is estimated. Preserve the source's study paths and information unless the user explicitly approves changes.

## Without a useful reference

Proceed with independent design; a missing example is not a blocker or a reason for a crude layout. Follow [independent layout](independent-layout.md), the actual study relationships and the selected visual style. State that no close example was used, rather than inventing one. The proposal must still cover the eight design dimensions, then wait for confirmation.

## Compare at the right level

Review visual balance, reading order, spacing rhythm, legibility and attachment correctness. Similar visual proportions matter more than matching exact dimensions, fonts or corner radii. Avoid both crowded boxes and long empty connector corridors. A small outer margin does not imply dense internal spacing.

For a supplied original, check node/branch/merge completeness explicitly. For a new design, check the approved plan. Never simplify research content to fit a style. One overall visual review is normally sufficient; iterate only for a concrete readability, logic or export problem.

## Shared geometry

Side exclusions leaving a transition attach to a trunk using branch_from; real node-level forks may still leave boxes. Align a side box with its junction when this improves readability. Boxes fit text plus comfortable padding; width_group coordinates peer boxes without requiring universal widths. Counts may be inline or separate according to the selected presentation. These are adaptable layout devices, not fixed coordinates.
