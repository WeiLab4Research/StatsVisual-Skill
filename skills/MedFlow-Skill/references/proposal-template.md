# Proposal template: eight design dimensions

Write the proposal in the user's language. Use the eight priority types as references where they fit; otherwise recommend a named custom diagram. Present one coherent recommended plan rather than unnecessary alternatives.

| Dimension | Specify before drawing |
|---|---|
| 1. Positioning | Diagram type/name, application context, core communication goal; priority/custom route and why it fits |
| 2. Content organisation | Necessary information, core nodes, supporting information, inclusions/exclusions and source locations; distinguish facts, assumptions and unknowns |
| 3. Logical structure | Temporal order, parallelism, hierarchy, containment, dependencies and feedback; meaning and direction of links |
| 4. Layout | Reading direction, module regions, node ordering, alignment and space allocation; final intended dimensions |
| 5. Graphical encoding | Node shapes, arrows, borders and grouping containers; mapping of each visual device to an already supported distinction |
| 6. Visual style | General or selected journal reference; palette, font, sizes, line widths, padding and visual hierarchy; visual style never determines scientific content |
| 7. Reference basis | Relevant academic examples or professional drawing guidance, actual citations/links when available, verified requirements versus observed conventions; state unmatched or unverified references |
| 8. Validation and delivery | Content/logic and visual checks, counts/units or conditions where relevant, three-format export plan, renderer limits and unresolved items |

No figure title or explanatory annotations on the canvas; use compact white-canvas cropping with about 6 pt outer padding. Final delivery is editable SVG, native editable PPTX and vector PDF only. Keep captions and explanatory information in the proposal/manuscript.

End with a request to confirm or revise the plan and stop before drawing. Actual confirmation, not passage of time or a guessed response, authorises rendering. Save `proposal.md`; after approval, record the user's real words, proposal version and current specification digest. Do not invent methodological, clinical or numerical facts to complete a plan. Material changes need a revised proposal and confirmation; layout refinements may remain within existing authorisation.

Before presenting the plan, follow [reference inspection](reference-learning.md). Include observed trunk-versus-node attachments, text fitting, width groups and final comparison criteria; preserve source topology unless simplification is explicitly approved.

## Flexible layout and missing references
Exact sizes, spacing and equalities are not required. Numeric defaults are advisory; keep readable text, clean routes and balanced proportions. Without useful examples, use [independent layout](independent-layout.md) and describe the reasoning briefly. A separate reference-review.md is optional; one overall visual review normally suffices. Content, path preservation, confirmation and editable three-format delivery remain required.
